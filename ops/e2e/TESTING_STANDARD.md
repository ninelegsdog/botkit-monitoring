# Стандарт тестирования (testing standard)

Каждый тест в `ops/e2e/tests/` должен отвечать на вопрос:
**«Какой реальный дефект этот тест поймает?»**

## Обязательные элементы теста

1. **Docstring** с описанием:
   - Какой дефект тест ловит
   - Почему этот дефект возможен
   - Ссылка на инцидент (если применимо)

2. **Assertion на содержимое, а не на форму:**
   - ❌ `assert file.exists()` — проверяет форму
   - ✅ `assert stat.S_IMODE(os.stat(file).st_mode) == 0o644` — проверяет содержимое
   - ❌ `assert "substring" in output` — проверяет форму
   - ✅ `assert {"branch_a", "branch_b"} <= set(result)` — проверяет все ветки

3. **Проверка parity с каноном** (для скриптов/юнитов):
   - Установленный файл == канон (cmp)
   - Не только HEAD коммита, а содержимое

4. **Проверка актуальности** (для клонов/синков):
   - HEAD клона == origin/main
   - Не только «клон существует»

## Шаблон теста

```python
def test_example():
    """Краткое описание дефекта, который ловит тест.

    Подробное описание: почему дефект возможен, как он проявляется,
    ссылка на инцидент (если применимо).
    """
    # Arrange
    ...

    # Act
    ...

    # Assert — проверяем СОДЕРЖИМОЕ, а не форму
    assert ...
```

## Категории тестов

1. **Contract tests** (test_*_contract.py): статический анализ скриптов/юнитов.
   Проверяют: parity, mode, наличие required элементов.
2. **Integration tests** (test_*_gate.py): запуск реальных скриптов со stubbed
   зависимостями. Проверяют: поведение, запись файлов, exit codes.
3. **Scenario tests** (test_scenarios.py): E2E-сценарии. Проверяют: ответы ботов.
   State-dependent views используют expect_any.

## Антипаттерны (не делать)

- ❌ Тест, который проверяет только `file.exists()` или `rc == 0`
- ❌ Тест, который проверяет только HEAD коммита, а не содержимое
- ❌ Тест, который проверяет только одну ветку state-dependent view
- ❌ Тест без docstring
- ❌ Тест, который проверяет «форму» (наличие), а не «содержание» (корректность)
